Qual IA usar para programar Angular?

Em 2026 a resposta mudou várias vezes. Este guia resume os 9 artigos da série (mai–set/2026) em um só lugar: modelo, harness, app, custo e privacidade.

Em 30 segundos

  • Modelos (ago/2026): 🥇 Fable 5 (arquitetura e problemas longos), 🥈 GPT‑5.6 Sol (implementação do dia a dia), 🥉 GLM‑5.3 Flash (rápido e barato para trabalho mecânico).
  • Fluxo preferido do autor: o modelo caro planeja e revisa; um modelo mais barato implementa como sub‑agente.
  • O harness importa tanto quanto o modelo: o mesmo modelo rende bem diferente em ferramentas diferentes.
  • Métrica que importa: custo por mudança aceita, revisada e mergeada — não preço por token.
  • Sempre: revisar todo diff e nunca enviar segredos ou dados de produção para a IA.

⚠️ É uma opinião pessoal baseada em trabalho real com Angular, não um benchmark científico. Os próprios autores repetem: teste no seu código. Números são fotos de datas específicas.

Perfil de cada modelo

E os outros?

  • Gemini / Antigravity: o autor acha o Google “bem atrás” dos três grandes; o Gemini tende a usar idiomas antigos de Angular e precisa de mais direcionamento.
  • Modelos chineses (DeepSeek, Qwen, Kimi, GLM): melhoraram muito; GLM‑5.3 Flash entrou no pódio. Kimi K3 e GLM‑5.3 completos chegam a 69%, mas custam ~€4 por tarefa.
  • Europeus (Mistral): opção estratégica quando residência de dados importa, não líderes em código.
  • Locais / open‑weight: úteis para privacidade e CI, mas ainda não no nível dos favoritos para Angular corporativo. Atenção: “open weights” não é “open source”.

Modelo, harness e app não são a mesma coisa

ModeloO cérebro (ex.: Opus, GPT). Só gera texto.
HarnessO software em volta: dá ferramentas (ler, buscar, editar, rodar ng build) e executa o laço “propõe → executa → lê resultado → decide”.
AppA janela onde você vê tudo (desktop, terminal, extensão de IDE).

O mesmo harness vive em vários apps (Claude Code roda no app desktop, CLI, VS Code, JetBrains). E o mesmo modelo muda de resultado conforme o harness: num teste da Artificial Analysis com o mesmo Opus 4.7 (medium), opencode fez 51, Cursor CLI 47 e Claude Code 42.

Apps (“super apps”)

  • T3 Code — open source, qualquer modelo/provedor, controle remoto pelo celular via Tailscale, sidebar tipo “caixa de entrada”.
  • Codex app — o mais polido; ótimo para “computer use” (navegador, screenshots). Só modelos da OpenAI.
  • Claude Desktop — casa natural do Claude Code; fora do pódio desde que o T3 Code faz o mesmo com mais modelos.
  • Cursor — melhor integração com IDE e agentes na nuvem; atenção: acesso a modelos OpenAI via Cursor pode acabar em 12/nov.
  • Antigravity 2.0 — promissor, mas ainda “desajeitado e com bugs”.

Harnesses e IDEs

  • opencode — open source, agnóstico de modelo; ponto de partida recomendado no terminal.
  • Pi — minimalista, para quem gosta de customizar.
  • Claude Code — excelente para orquestrar sub‑agentes (.claude/agents/), hooks e /loop.
  • Cline — extensão open source para VS Code/JetBrains; pode usar suas assinaturas.
  • VS Code + Copilot — o autor desaconselha como base: o agente ainda fica um passo atrás.
  • WebStorm + Junie — bom para trabalho cuidadoso “feito à mão”.

Seu código também é um fator

O agente imita o que lê. Em código limpo e moderno, ele escreve código limpo. Em legado (NgModules, *ngIf, RxJS onde caberiam signals), ele copia a bagunça. Quanto pior o código, mais o setup do harness importa.

Valores do artigo de ago/2026 (por milhão de tokens, sem desconto de cache/batch). Ajuste e veja o custo de um “turno” do agente.

Esforço de raciocínio

  • Low — edições pequenas · Medium — implementação normal · High — bugs difíceis, criar componente, refatoração · Extra/Max — quando errar custa mais que os tokens.
  • Regra do autor: comece em high; se o resultado for perfeito, reduza. Para o Fable, medium já basta (65% no DeepSWE por ~€5,50/tarefa).

Como economizar o Fable

  1. Sol é o padrão, Fable é a exceção (vago, arquitetura, revisão, longo prazo).
  2. Esforço medium/high, não max (max dobra a conta por ~1 ponto).
  3. Planeje antes, depois deixe rodar.
  4. Contexto enxuto: thread nova por tarefa, AGENTS.md curto, pouca saída de terminal.
  5. Delegue o trabalho braçal a um sub‑agente mais barato.

Custo por tarefa no DeepSWE (high → max): Fable ≈ €8,50 → €20 · Opus 5 ≈ €5,50 → €11 · GPT‑5.6 Sol ≈ €2,50 → €6 · GLM‑5.3 Flash ≈ €0,25.

Privacidade: não proíba, aprove caminhos seguros

Agentes enviam muito mais que o prompt: trechos de código, diffs, saída de terminal, caminhos, screenshots, stack traces… E eles executam comandos, o que cria risco de vazamento (a “tríade letal”: dados privados + conteúdo não confiável + saída para a rede).

🟢 Verde

Aprendizado, experimentos, código público/open source. Assinatura pessoal serve.

🟡 Amarelo

Código proprietário. Só em termos aprovados: business, team, enterprise ou API.

🔴 Vermelho

Segredos, credenciais, dados de produção/clientes/pessoais regulados. Nunca no contexto da IA.

  • “Sem treino” ≠ “sem retenção”. Provedores podem reter dados por abuso, segurança, depuração ou obrigação legal.
  • Planos pessoais vs. comerciais: pessoais podem usar seus dados para treino se você não desativar; planos comerciais e API normalmente não treinam por padrão.
  • Fable 5: exige retenção de 30 dias, sem opção de zero retenção — pode inviabilizar setores regulados.
  • Esconda segredos do agente: bloqueie .env, *.pem, *.key e environment*.ts (no Claude Code, via permissions.deny).
  • Na UE: LGPD/GDPR, contrato de processamento de dados, residência de dados e, a partir de 2/ago/2026, fiscalização do AI Act.
Perguntas a fazer a qualquer fornecedor
  • Meu código é usado para treino por padrão? Dá para desativar na organização toda?
  • O que é retido, onde e por quanto tempo? Há zero retenção ou processamento regional?
  • Quais subprocessadores? Há revisão humana?
  • Como tratam prompts, diffs, screenshots e saída de terminal?
  • Admins podem desligar conectores, navegador, servidores MCP e agentes na nuvem?

Setup do harness para Angular (5 passos)

O repositório de exemplo do autor é o ng-agentic. A ideia: o agente só escreve o Angular que você quer se o ambiente disser como.

  1. Base limpa

    Comece de um ng new atual (ou identifique a base legada que você já tem).

  2. Formatação e lint obrigatórios

    Hook de pre‑commit (Husky) para rodar Prettier/ESLint em todo commit, venha o código de você ou da IA.

  3. Guia de estilo ⭐

    O arquivo de maior alavancagem de todo o setup. O modelo sabe Angular genérico; o guia diz como seu time escreve (Vitest em vez de Jest, signals em vez de RxJS, zoneless, etc.).

  4. AGENTS.md como contrato

    Regras de comportamento: preserve minhas edições, correções locais e mínimas, não toque em arquivos alheios, rode lint e testes antes de dizer “pronto”, não suba o ng serve.

  5. Ligue todos os agentes

    Um arquivo fino por ferramenta (Cursor, Cline, Gemini, Copilot…) apontando para o mesmo AGENTS.md. Registre servidores MCP uma vez (Angular CLI, Chrome DevTools, Figma) — isso também contorna o corte de conhecimento do modelo.

Laços de feedback (do mais barato ao mais caro)

ng lintregras estáticas→ ng buildcompila tudo?→ servevocê roda, agente usa→ Chrome debugconsole e rede→ E2EPlaywright/Cypress

Melhor feedback é o que o harness força (hooks), não o que o agente apenas “promete” fazer.

Skills: prompt bom ajuda uma vez, skill boa ajuda sempre

Uma skill é uma pasta com um SKILL.md (padrão aberto Agent Skills) que o agente só carrega quando a tarefa pede. Em vez de lotar o AGENTS.md, você guarda ali procedimentos: quais passos, quais portões, quem faz o commit.

Exemplos do catálogo (31 skills)

  • ng-refactor — moderniza um componente legado em 7 passos, com checkpoint humano em cada um.
  • ng-forms — Signal Forms.
  • ng-data-access — httpResource(), resource().
  • ng-signal-store — só cria store se o estado for mesmo compartilhado.
  • ng-testing / create-e2e-tests — Vitest e Playwright.
  • ng-security, ng-accessibility, ng-performance, ng-migrate.

Como escrever uma boa skill

  • Escreva a descrição para o gatilho: “o que faz + quando usar”.
  • Mantenha o SKILL.md enxuto (< 500 linhas); detalhes vão em references/.
  • Codifique processo, não conhecimento que o modelo já tem.
  • Decida quem pode disparar (humano, modelo ou ambos).
  • Skills pequenas que delegam entre si.
  • Copie só o que seu projeto usa: cada skill ocupa contexto.

Skills expiram: algumas existem só porque um modelo antigo não era confiável sem elas. Reavalie a cada nova geração.

Conclusões da série

  • O modelo importa — saiba quando usar cada um.
  • O harness importa — é a alavanca que você controla.
  • O custo real é por mudança aceita, não por token.
  • A privacidade importa — aprove caminhos seguros em vez de só proibir.
  • Você continua responsável pelo diff final. Julgue tudo no seu código, com suas tarefas e seus padrões de revisão.
